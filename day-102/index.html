1. 为什么需要 Pandas

从 NumPy 到 Pandas

NumPy 擅长数值计算，但数据分析还需要：
- 列名/行标签：NumPy 数组没有语义标签
- 混合类型：一列可以是字符串，另一列是数字
- 缺失值处理：真实数据总有 NaN
- 便捷的数据操作：筛选、分组、合并

NumPy ndarray:           Pandas DataFrame:
┌──────────────┐         ┌──────────┬────────┬──────┐
│ 1    2    3  │         │ 姓名     │ 年龄   │ 城市 │
│ 4    5    6  │   →     ├──────────┼────────┼──────┤
│ 7    8    9  │         │ 张三     │ 25     │ 北京 │
└──────────────┘         │ 李四     │ 30     │ 上海 │
(纯数值，无标签)          └──────────┴────────┴──────┘
                         (有列名，有行索引)

Pandas 的两大核心结构

Series   → 一维带标签数组（类比 Excel 的一列）
DataFrame → 二维带标签表格（类比 Excel 的一个 sheet）

5. 数据选择：loc / iloc / 布尔索引

三种选择方式对比

┌─────────────────────────────────────────────────┐
│              DataFrame 数据选择                  │
├─────────────────────────────────────────────────┤
│                                                 │
│  loc  → 按标签选择（label-based）               │
│  iloc → 按位置选择（integer-based）              │
│  []   → 列选择 + 布尔索引                       │
│                                                 │
└─────────────────────────────────────────────────┘

loc — 按标签选择

python
df = pd.DataFrame({
    '姓名': ['张三', '李四', '王五'],
    '年龄': [25, 30, 35],
    '城市': ['北京', '上海', '广州']
}, index=['a', 'b', 'c'])

# 选择单行
print(df.loc['a'])
# 姓名    张三
# 年龄     25
# 城市    北京

# 选择多行
print(df.loc[['a', 'c']])

# 选择行和列
print(df.loc['a', '年龄'])           # 25
print(df.loc['a':'b', ['姓名', '城市']])  # a 到 b 行的指定列

# 条件选择
print(df.loc[df['年龄'] > 25])

iloc — 按位置选择

python
df = pd.DataFrame({
    '姓名': ['张三', '李四', '王五'],
    '年龄': [25, 30, 35],
    '城市': ['北京', '上海', '广州']
})

# 选择第 0 行
print(df.iloc[0])

# 选择第 0-1 行，第 1-2 列
print(df.iloc[0:2, 1:3])

# 选择指定行和列
print(df.iloc[[0, 2], [0, 2]])

# 条件选择（注意：iloc 不支持布尔索引，需要先用 loc）
print(df.iloc[df.index[df['年龄'] > 25].tolist()])

列选择与布尔索引

python
# 直接选择列
print(df['姓名'])           # Series
print(df[['姓名', '年龄']])  # DataFrame

# 布尔索引
mask = df['年龄'] > 25
print(df[mask])              # 等价于 df[df['年龄'] > 25]

# 多条件（用 & | ~，不是 and or not）
print(df[(df['年龄'] > 25) & (df['城市'] == '上海')])
print(df[(df['年龄'] < 28) | (df['城市'] == '广州')])
print(df[~(df['年龄'] > 30)])  # 取反

选择方式总结

场景 推荐方式 示例
按行标签 loc df.loc['row_name']
按行位置 iloc df.iloc[0]
选择列 [] df['col_name']
条件筛选 布尔索引 df[df['col'] > value]
行+列组合 loc df.loc['a':'c', ['col1']]
位置+列组合 iloc df.iloc[0:3, 0:2]

8. 实战：加载 CSV 数据探索

模拟电商数据

python
import pandas as pd
import numpy as np
import os

# 生成模拟数据
np.random.seed(42)
n = 1000

products = np.random.choice(['手机', '电脑', '耳机', '平板', '手表'], n)
categories = np.where(np.isin(products, ['手机', '电脑', '平板']), '电子',
              np.where(np.isin(products, ['耳机']), '配件', '穿戴'))
prices = np.where(products == '手机', np.random.uniform(2000, 6000, n),
         np.where(products == '电脑', np.random.uniform(4000, 12000, n),
         np.where(products == '耳机', np.random.uniform(100, 2000, n),
         np.where(products == '平板', np.random.uniform(1500, 5000, n),
                  np.random.uniform(500, 3000, n)))))
quantities = np.random.randint(1, 10, n)
discounts = np.random.choice([0, 5, 10, 15, 20], n, p=[0.3, 0.3, 0.2, 0.15, 0.05])
cities = np.random.choice(['北京', '上海', '广州', '深圳', '杭州', '成都', '武汉'], n)
dates = pd.date_range('2024-01-01', periods=n, freq='D')

df = pd.DataFrame({
    '日期': dates,
    '产品': products,
    '类别': categories,
    '单价': np.round(prices, 2),
    '数量': quantities,
    '折扣%': discounts,
    '城市': cities,
    '总金额': np.round(prices * quantities * (1 - discounts / 100), 2)
})

# 保存为 CSV
os.makedirs('days/day-102-pandas-核心/data', exist_ok=True)
df.to_csv('days/day-102-pandas-核心/data/ecommerce.csv', index=False)
print(f"数据已保存，共 {len(df)} 条记录")

9. 思考题

  1. loc 和 iloc 的本质区别是什么？在什么场景下必须用 loc 而不能用 iloc？

参考答案

本质区别是「按什么找数据」：

  • loc 按标签（label）——行索引的名字、列的名字。
  • iloc 按整数位置（position）——第几行、第几列，从 0 数起，和列表下标一样。

当索引是默认的 0,1,2… 时两者结果常常一样，容易混淆；一旦索引被换成有意义的标签，差别就出来了。例如 df.index = ['a','b','c'] 后，df.loc['a'] 取第一行，而 df.iloc['a'] 直接报错（iloc 只认整数）。

必须用 loc 的场景：
- 索引是字符串/日期等非整数标签，要按名字取行，如 df.loc['2024-01-01']。
- 标签切片 df.loc['a':'c']——包含末端 'c'；而 iloc[0:2] 是位置切片，不含末端，两者语义不同。
- 按列名同时选行列：df.loc['a', '年龄']。

⚠️ 注意：若索引恰好是整数但不连续或乱序（如 [10, 20, 30]），loc[10] 找标签 10，iloc[10] 找第 11 行（可能越界）——这时绝不能混用。

  1. DataFrame 的 [] 操作符在选择单列和多列时，行为有什么不同？为什么？

参考答案

  • 单列 df['年龄'] → 返回 Series（一维，带索引）。
  • 多列 df[['姓名','年龄']] → 返回 DataFrame（二维表格）。

注意多列要传一个列表（双层括号），内层 ['姓名','年龄'] 是列名列表，外层 df[...] 是取值操作。

为什么这样设计：单列天然是一维数据，用 Series 表示最自然，还能直接做 .mean() 等向量运算；多列仍是表格，保留 DataFrame 结构才能继续做行列操作。这也解释了为什么 df['姓名'] 能 .str.upper() 而 df[['姓名']] 不能——后者是 DataFrame，没有 .str 访问器。

💡 提示：想要「单列但保持 DataFrame 形状」（比如为了后续 concat 对齐），就用双层括号 df[['年龄']]，它返回只有一列的 DataFrame。

  1. 为什么 df[df['A'] > 1 & df['B'] > 2] 会报错？正确的写法是什么？运算符优先级的原理是什么？

参考答案

因为 & 的优先级高于 >。Python 会先把式子解析成 df['A'] > (1 & df['B']) > 2——这是一个「链式比较」，等价于 (df['A'] > (1 & df['B'])) and ((1 & df['B']) > 2)。其中 1 & df['B'] 把整数和 Series 做位运算，再对结果 Series 取布尔值，于是抛出「Series 真值不明确」之类的错误（不同 pandas 版本报 TypeError 或 ValueError）。

正确写法：给每个比较加括号，让 > 先算、再做 &：

python
import pandas as pd

df = pd.DataFrame({'A': [1, 2, 3], 'B': [3, 4, 1]})

# 错误写法：& 优先级高于 >，被解析成链式比较 df['A'] > (1 & df['B']) > 2
try:
    df[df['A'] > 1 & df['B'] > 2]
except (TypeError, ValueError) as e:
    print("报错:", type(e).__name__, "-", e)

# 正确写法：每个比较都加括号
print(df[(df['A'] > 1) & (df['B'] > 2)])

预期输出（报错类型因 pandas 版本而异）：

报错: ValueError - The truth value of a Series is ambiguous. Use a.empty, a.item(), a.any() or a.all().
   A  B
1  2  4

原理：Python 运算符优先级里，位运算 & | ^ 排在比较运算 > < == 之前，而 pandas 的逐元素逻辑运算恰恰要用 & | ~（不能用 and or not，后者只能处理单个布尔值）。所以多条件筛选务必写成 (条件1) & (条件2)。

  1. query 方法和布尔索引在性能上有什么区别？大数据量下推荐用哪个？

参考答案

两者底层都是生成布尔掩码再筛选，但开销来源不同：

  • 布尔索引 df[(df['A']>1) & (df['B']>2)]：直接调用 NumPy 向量化运算，没有额外解析开销，小数据下通常最快。
  • query('A>1 & B>2')：先把字符串表达式解析成计算图，再交给 numexpr（若安装）或 pandas 引擎求值。字符串解析有一次性开销，但 numexpr 能多线程 + 减少中间临时数组，在超大 DataFrame、复杂表达式上反而更快、更省内存。

推荐：
- 小到中等数据、简单条件 → 布尔索引，直观且快。
- 超大表（百万行以上）、多条件复杂表达式、或想少写 df['...'] 让代码更清爽 → query（配合 numexpr 收益明显）。

💡 提示：query 里引用外部变量用 @（如 df.query('A > @threshold')）；列名含空格或特殊字符时需用反引号包裹。性能差异因数据规模/是否装 numexpr 而异，建议实测。

  1. 读取一个 10GB 的 CSV 文件，pd.read_csv() 一次性加载可能内存不够，有什么解决方案？（提示：chunksize 参数）

参考答案

核心思路是分块流式处理：用 chunksize 让 read_csv 返回一个迭代器，每次只读 N 行进内存，处理完即释放，内存占用恒定。

python
import io
import pandas as pd

# 用内存中的 CSV 文本模拟大文件（真实场景换成 'big.csv' 路径即可）
csv_text = "id,value\n" + "\n".join(f"{i},{i * 2}" for i in range(1000))

total, rows = 0, 0
for chunk in pd.read_csv(io.StringIO(csv_text), chunksize=100):
    # 每次只拿到 100 行，内存占用恒定
    rows += len(chunk)
    total += chunk['value'].sum()   # 分块累加，最后汇总

print(f"共 {rows} 行, value 总和 = {total}")

预期输出：

共 1000 行, value 总和 = 999000

除了分块，还可组合这些手段降低内存：
- 只读需要的列/行：usecols=['id','value']、nrows=...。
- 指定更小的 dtype：dtype={'id':'int32'}，或用 category 存重复字符串。
- 换存储格式：把 CSV 转成 Parquet（列式 + 压缩），读取更快更省。
- 换引擎：数据实在太大时用 Dask/Polars 的惰性、并行读取。

⚠️ 注意：分块适合「可逐块累加」的统计（求和、计数、过滤）；若需要全局排序、跨块 join，则要先分块落盘再合并，或直接用 Dask 这类分布式框架。
