# Day 194 概念卡 — AI 增强与数据管道

一页纸版本，配合 README 使用。所有数字来自 2026-10-24 本机实测。

---

## 1. 为什么软封必须用模型

| 拒绝方式 | 响应特征 | 规则能不能抓 |
|---|---|---|
| 硬封 | 403 / 401 + WAF 页 | ✅ |
| 限速 | 429 / 503 + Retry-After | ✅ |
| 软封 | 200 + 空壳页 + 正常响应头 | ❌ 无单点特征 |

软封只能靠组合信号：body_len 异常小、header_count 少、latency 高、偶发验证码。
实测规则基线在 899 条测试样本上漏 57 条软封、误报 222 条正常页。

## 2. 模型选择：为什么是逻辑回归

| 维度 | 逻辑回归 | LLM 逐页判断 |
|---|---|---|
| 单条推理 | 6.9 µs（批量 0.02 µs/条） | 数百毫秒 |
| 边际成本 | 0 | 每千页数元 |
| 可解释 | 系数直接看 | 需要额外解释 |
| 依赖 | numpy | 网络 + API key + 额度 |

高频二分类 → 特征工程 + 轻量模型。语义理解类低频任务才轮到 LLM。

## 3. 三个必须记住的指标陷阱

1. **accuracy 会骗人**：正类只占 25.4%，全判"安全"就有 74.6%。
2. **阈值 0.5 不是最优**：漏报代价 = 误报 × 5 时，最优阈值 0.34，
   总代价 194 → 144（漏报 26、误报 14）。
3. **离线指标可能来自泄漏**：把只有被拦后才存在的字段（`waf_reason`）喂进模型，
   离线 AUC 会虚高。本次实验里隐藏变量单列 AUC 就有 0.8957。

## 4. 去重的三层结构

```text
第一层  精确哈希   SHA256(归一化文本)      P 1.000 / R 0.164
第二层  SimHash    64 位指纹 + 分桶索引    P 1.000 / R 0.539 (k=3)
                                          候选压到 0.06%
第三层  Jaccard    token 集合交并比 ≥ 0.6  终判 P 1.000 / R 0.853
```

- 精确哈希只能抓原样复制；
- SimHash 单独用，k 无法同时兼顾精度与召回（k=10: P 0.923；k=15: P 0.153）；
- 粗筛 + 精排才是生产解。

**短文本例外**：10 token 的商品标题，改一个价格，汉明距离中位数 8；
k=3 召回只有 3.0%，而 k=8 时无关标题误判 2.30%。短文本用集合相似度或规则。

## 5. 分桶索引的取舍

| bands | 每段位宽 | 保证召回 k | 平均候选/篇 | 实测候选对 |
|---|---|---|---|---|
| 4 | 16 | 3 | 1.5 | 285 |
| 8 | 8 | 7 | 1.8 | 454 |

鸽巢原理：距离 ≤ bands-1 时至少一段完全相同。段越细保证阈值越高，
但每段取值空间变小、桶变挤。超过 bands-1 的 k 必须换别的结构，
否则召回没有保证（库里直接抛 `ValueError`）。

## 6. 管道的四条硬规矩

1. **分阶段**：每段有输入/输出计数，错误可定位。
2. **脏数据进隔离区**，带 reason code，不静默丢。
3. **入库 UPSERT 幂等**，但幂等不等于正确（见 `03` 的 419 页事故）。
4. **质量门禁只写可判定规则**，需要判断的进人工队列。

实测漏斗（3000 条）：去重丢 349（11.6%）→ 质检拦 885（29.5%）→ 入库 2115，
总耗时 2556 ms（1,173 条/s），其中去重占 88.2%。

## 7. 一句话记忆

- 规则管显式拒绝，模型管软封；
- 精确哈希管复制，SimHash 管改写，Jaccard 管终判；
- 分桶管规模，阈值管权衡；
- 幂等管重跑，门禁管质量，隔离区管"丢了多少"。
