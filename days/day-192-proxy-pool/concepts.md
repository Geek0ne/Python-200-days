# Day 192 概念词典 — 代理池

> 每个词条都回答三件事：是什么、为什么存在、怎么观测。
> 面向"要写一个能过夜的爬虫"的读者，不是网络考试。

---

## 1. 出口（Exit）

**定义**：目标站看到的那个来源 IP，以及它背后的一整套网络身份（ASN、地区、TLS 指纹）。

**为什么不用"代理"这个词**：一台代理可能对应多个出口 IP（轮换型供应商），
一个出口 IP 也可能被多台代理共用。爬虫真正关心的是"目标站把我认成谁"，
所以调度单位是出口，而不是代理 URL。

**观测**：向受控靶站发一次请求，读回它看到的源 IP / 标记。
本课用 \`X-Exit-Id\` 注入，生产可用 \`/ip\` 端点。

---

## 2. 透明 / 匿名 / 高匿代理

| 类型 | 目标站看到 | 风险 |
|---|---|---|
| 透明 | 你的真实 IP + \`X-Forwarded-For\` | 等于没代理，还会暴露内网结构 |
| 匿名 | 代理 IP，但能识别出用了代理 | 部分站点直接拒绝 |
| 高匿 | 只看到代理 IP，无代理痕迹 | 爬虫唯一可用类型 |

**为什么重要**：很多"免费代理列表"里 80% 是透明代理。
用它们不是"隐藏"，是"主动上报"。

---

## 3. 正向代理与绝对 URI

**定义**：客户端把完整目标 URL 放进请求行，交给代理转发。

\`\`\`http
GET http://target.example/item/1 HTTP/1.1
Host: target.example
\`\`\`

**为什么这样设计**：代理需要知道"往哪转发"，而普通请求行只有路径。
所以正向代理收到的是绝对 URI，反向代理收到的是普通路径。

**坑**：自己写代理时若只解析 \`self.path\` 当路径用，会得到 400 或转发到错误主机。

---

## 4. CONNECT 隧道

**定义**：客户端对代理说 \`CONNECT host:443 HTTP/1.1\`，代理建立 TCP 连接后
回复 \`200 Connection Established\`，之后双方只转发字节流。

**为什么必须**：HTTPS 的 TLS 握手是端到端的，代理不能解密（也不该）。
没有 CONNECT，代理无法承载任何 HTTPS 请求。

**观测**：\`URLError: Tunnel connection failed: 501 Not Implemented\`。

---

## 5. 407 Proxy Authentication Required

**定义**：代理自身的鉴权挑战，配 \`Proxy-Authenticate: Basic realm="..."\`。

**与 401 的区别**：401 是目标站要你登录，407 是代理要你付费/认证。
HTTP 头也不同：\`Proxy-Authorization\` vs \`Authorization\`。

**安全要求**：\`Proxy-Authorization\` 只能发给代理，绝不能透传给目标站。

---

## 6. 健康检查（Health Check）

**定义**：主动发起一次可验证的请求，判断出口是否"真的能用"。

**三个层次**：

1. **L3/L4**：TCP 能连 —— 只证明进程活着；
2. **L7 任意响应**：能拿到 HTTP 状态 —— 可能被劫持到登录页；
3. **L7 可验证响应**：状态 200 + 预期标记 —— 唯一可信。

**频率设计**：出口数 × 频率 就是你的额外请求量。
100 个出口 × 每 10s = 10 req/s 的纯检查流量，足以触发部分站点限流。
生产做法：分层（快探 30s、业务慢探 5min）+ 只在低水位时全量探。

---

## 7. 出口评分（Score）

\`\`\`text
score = success_rate² / (1 + ewma_latency)
\`\`\`

**为什么平方**：让"经常失败"的出口快速掉队。0.9 → 0.81，0.5 → 0.25。

**为什么 EWMA**：\`new = α·sample + (1-α)·old\`，α 常取 0.2–0.3。
出口恢复后十几次请求就能回到高分，不会被历史永久封印。

**冷启动**：所有出口初始分相同，纯 argmax 会永远选第一个。
必须给新出口一次强制探针（本课实现：\`requests == 0\` 优先）。

---

## 8. 熔断（Circuit Breaker）

**定义**：连续失败达到阈值后，直接拒绝分配，不再"试一试"。

**三种状态**：

- **Closed**：正常放行；
- **Open**：拒绝分配（冷却中）；
- **Half-Open**：冷却到期，放一个探针；成功→Closed，失败→Open 且冷却加倍。

**为什么不能"失败就重试"**：重试把单点故障放大成 N 倍流量，
而且会让目标站看到"同一个出口在被反复捶"，加速封禁。

---

## 9. 冷却（Cooldown）与 Retry-After

**定义**：一段时间内不使用某出口。

**时长来源**（优先级从高到低）：

1. 响应头 \`Retry-After\`（秒数或 HTTP 日期）；
2. 指数退避 \`base × 2^n\`，封顶；
3. 业务配置的默认值。

**为什么尊重 Retry-After**：服务端已经给出"多久后再来"。
提前来 = 告诉对方"我不在乎你的规则"，这是行为指纹，不是 IP 指纹。

---

## 10. 令牌桶（Token Bucket）

**定义**：以固定速率补充令牌，请求前必须先取到令牌。

\`\`\`text
capacity = 2, rate = 1/s
t=0.0  tokens=2  → 连发 2 个
t=0.5  tokens=0  → 等 0.5s
t=1.0  tokens=1  → 发 1 个
\`\`\`

**capacity 的含义**：允许的瞬时突发。设成 rate 会让短任务速率翻倍。

**必须按出口建桶**：全局一个桶只限制"你总共多快"，
不限制"每个 IP 多快"；而目标站是按 IP 记账的。

**实现坑**：等待与扣减必须在同一临界区。分开写会出现"等完不扣"，
实测速率比配置高 34%。

---

## 11. 粘滞会话（Sticky Session）

**定义**：同一业务域（或同一账号）固定使用同一出口。

**为什么**：cookie、登录态、CSRF token、风控评分都依赖"连续性"。
10 秒内跨 3 个省登录，等于自报"我是分布式爬虫"。

**失效条件**：出口冷却 / 被封 / 手动摘除。迁移要计数，迁移率升高 = 池子太小或封禁加剧。

---

## 12. 出口池水位（Pool Water Level）

\`\`\`text
water_level = 可用出口数 / 总出口数
\`\`\`

**经验阈值**：

| 水位 | 状态 | 动作 |
|---|---|---|
| > 60% | 健康 | 正常调度 |
| 30–60% | 紧张 | 降速、补充出口 |
| < 30% | 危险 | 暂停任务、告警 |
| 0 | 熔断 | 全站暂停，别再打了 |

**为什么需要**：没有水位，池子会在"只剩 1 个出口"时继续满速跑，
直到最后一个也被封，任务彻底停摆。

---

## 13. 代理类型与选型

| 类型 | 延迟 | 成本 | 被识别难度 | 适用 |
|---|---|---|---|---|
| 数据中心 | 低（1–20ms） | 低 | 易（ASN 标记） | 公开数据、非风控站点 |
| 住宅 | 中（50–300ms） | 高 | 难 | 电商、社交、强风控 |
| 移动 | 高（100–800ms） | 很高 | 最难 | 移动端 API、验证码场景 |
| 自建（云主机） | 低 | 中 | 中（可控） | 长期稳定任务、合规采集 |

**选型原则**：先问"目标站的风控强度"，再问预算。
用住宅代理抓公开文档，是拿钱买心理安慰。

---

## 14. 观测指标清单

| 指标 | 计算 | 异常信号 |
|---|---|---|
| 成功率 | 2xx / 总请求 | < 80% 需排查 |
| p50 / p95 延迟 | 分位数 | p95 远高于 p50 = 长尾出口拖累 |
| 429 率 | 429 / 总请求 | > 5% = 速率配置过高 |
| 403 率 | 403 / 总请求 | 突增 = 指纹或 IP 段被封 |
| 出口水位 | 可用/总数 | < 30% 告警 |
| 迁移率 | 粘滞迁移次数/会话数 | 升高 = 池子不足 |
| 每出口请求分布 | 计数 | 极度不均 = 评分过拟合 |

---

## 15. 一页速查

\`\`\`text
请求前：过滤冷却 → 冷启动探针 → 粘滞复用 → 最高分
请求中：每出口令牌桶 → 超时上限
请求后：200 记成功/延迟；429 按 Retry-After 冷却；
        403 冷却；407 永久摘除；5xx 连续 N 次熔断
全局：水位监控、迁移率、p95、每出口分布
\`\`\`
