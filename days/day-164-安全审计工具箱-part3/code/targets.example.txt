# Day 164 · 流量审计目标清单（示例）
#
# 这个文件的来源：Day 162 资产面产出（端口扫描 + 目录爆破 + 指纹识别）
# 与 Day 163 漏洞面产出（带参数的端点）。
#
# 格式：一行一个 URL，`#` 开头是注释，空行忽略。
# 用途：告诉代理"这一轮审计该盯哪些 URL"，让 capture 的覆盖率有对照基准。
#
# ⚠️ 边界：只允许回环地址（127.0.0.1 / localhost / ::1）
#          与 RFC 5737 文档网段（192.0.2.0/24）。
#          其它主机一律被 Scope 门禁拒绝（退出码 2），不会发出任何请求。
#
# 为什么把"目标清单"和"捕获"绑在一起？
#   因为覆盖率的完整定义是**两层的**：
#     第一层：捕获到了多少流量（流量的覆盖面）
#     第二层：清单里有多少目标**从来没有出现过**在流量里（业务的覆盖面）
#   只看第一层会得出"覆盖率 100%"的假象——用户没点过的端点，流量里当然没有。

# ── 静态页面（基线：应当没有凭据、没有敏感参数）──
http://127.0.0.1:18081/
http://127.0.0.1:18081/health

# ── 查询类接口（重点：参数怎么传的）──
http://127.0.0.1:18081/api/user?id=1
http://127.0.0.1:18081/search?q=python

# ── 认证类端点（重点：凭据是否明文、Cookie 是否带标记）──
http://127.0.0.1:18081/login

# ── 跳转与权限边界 ──
http://127.0.0.1:18081/redirect?to=/login
http://127.0.0.1:18081/admin

# ── 性能相关（重点：慢响应 / 大响应 / 截断）──
http://127.0.0.1:18081/slow
http://127.0.0.1:18081/large
