# 别写「显然」：给技术文章装上可验证的结构

## 起因：一篇自我感觉良好的稿子

我给自己的文章写了一个结构体检器，第一件事是拿它检查我刚写好的稿子。结果是 65 分：

```text
评分 65/100   错误 2   警告 5
  ❌ L3    E001  出现第二个 H1：一篇文章只能有一个标题
  ⚠️ L7    W102  模糊断言「显然」：给出证据或删掉
  ❌ L9    E003  代码块没有标注语言（读者失去语法高亮）
  ⚠️ L15   W104  遗留 TODO/TBD：发布前处理掉或明确标注为邀请协作
  ⚠️ L19   W103  性能/数量断言缺少测量条件（样本量、环境、重复次数）
```

七个问题里，没有一个是"写错了"，全都是"读者没法信"。这篇文章讲的就是这七类问题中
最贵的两类：**没有证据的断言**，和**没有条件的数字**。

## 一、技术文章的三种失败

### 1.1 断言不可验证

"显然"、"众所周知"、"大家都知道"这类词，在作者脑子里是省略，在读者眼里是拒绝解释。
它们的共同点是：**把举证责任推给读者**。技术读者的耐心恰好用在这上面最亏。

### 1.2 数字没有条件

"速度快了 3 倍"这句话缺四个要素：测什么、在什么机器上、跑了几次、取哪个统计量。
少了任何一个，读者都无法判断这个数字是否适用于自己。

下面这张卡片是我对体检器本身做的测量，格式可以直接照抄：

```text
- 命令：python3 01-article-lint.py /tmp/day199/big.md
- 环境：Python 3.12.3 / Linux 7.0.0-34-generic / x86_64 / 4 核 / load1=5.35
- 重复：5 次，取 median
- 耗时：min 116.93 ms · median 130.84 ms · max 133.38 ms（极差/中位 12.6%）
- 退出码 0，stdout sha256 前缀 f504041230f1c085
```

同一份命令在 636,684 字符的输入上重复 5 次，输出哈希完全一致——这才能叫"可复现"。

### 1.3 结构没有入口

一篇 3000 字没有小标题的文章，读者只能线性读。目录不是装饰，它是**读者的第一个
判断依据**：这篇文章值不值得花五分钟。

## 二、把检查写成代码

体检器只有 245 行，规则刻意少而硬。核心是一个状态机：遇到代码围栏就切换状态，
围栏内的 `#` 不参与标题检查。

```python
m = FENCE_RE.match(line)
if m:
    if not in_fence:
        in_fence = True
        if not m.group(2):
            add("E003", "error", i, "代码块没有标注语言")
    else:
        in_fence = False
    continue
if in_fence:
    continue  # 代码内容不参与结构检查——这是最容易误报的地方
```

这条 `continue` 是整个工具的地基。没有它，代码块里的每一行 `# 注释` 都会被当成
一级标题，体检器会把自己变成一个噪音源。

评分公式也写死在代码里，读者可以自己算：

```text
score = max(0, 100 - 10 * errors - 3 * warnings)
```

一个 error 抵三个 warning。这不是科学，是产品判断：结构错误直接毁掉可读性，
措辞问题只是让读者多花点力气。

## 三、实测：体检器自己有多快

我用三种规模的合成文章压测，每档重复 5 次取中位数，输入分别是 400 / 2000 / 8000
个小节：

| 输入字符 | 行数 | median | 极差/中位 | 输出哈希稳定 |
|---|---|---|---|---|
| 30,483 | 3,201 | 44.06 ms | 22.8% | 是 |
| 156,684 | 16,001 | 59.18 ms | 21.5% | 是 |
| 636,684 | 64,001 | 130.84 ms | 12.6% | 是 |

两个结论：

1. **吞吐是线性的**。字符数翻 20 倍，耗时只从 44 ms 涨到 131 ms，因为约 20 ms 是
   解释器启动的固定成本。
2. **小文件的百分比噪声更大**。同一台机器 load1=5.35 时，30KB 输入的极差达到 22.8%，
   而 636KB 只有 12.6%——固定成本越小，被调度抖动影响的相对比例越大。所以引用
   "快了百分之几"这种小数时，样本量比绝对值更重要。

## 四、发布：零依赖静态站

渲染器只支持我需要的那部分 Markdown，但每个行为都是确定的：先转义再替换，
代码块里的 `<` 变成 `&lt;`，中文标题直接用原文当锚点。

```python
out = html.escape(text, quote=False)
out = re.sub(r"`([^`]+)`", lambda m: "<code>" + m.group(1) + "</code>", out)
```

构建产物是一个目录：文章页、首页、RSS、`.nojekyll`。`cp` 到任何静态服务器就能用。

```bash
python3 03-article-build.py article --out dist
python3 03-article-build.py article --out dist --serve 8899
```

## 五、发布前清单

- 只有一个 H1，标题层级不跳级
- 每个代码块都标了语言，读者能复制
- 没有"显然""众所周知"，每个断言有出处或实验
- 每个数字带环境、样本量、重复次数、统计量
- 至少一段命令，读者能照着跑出同样的输出
- 图片有 alt，链接有可读文字，没有遗留 TODO
- 段落不超过 400 字，小标题能独立成句

体检器能机械地查掉其中六条，第七条得自己读一遍。
