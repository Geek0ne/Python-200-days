## 一、为什么"收官日"很重要

新手最常见的坑：**学完就翻篇**。项目做完、代码跑通，立刻冲向下一个主题——两周后回头看，只剩模糊印象。工程界有个共识：**没有复盘的项目，只完成了 60%**。剩下 40% 的价值在复盘里：

1. **把"做过"变成"会讲"**——能向别人讲清楚架构决策，才算真懂
2. **沉淀可复用资产**——代理池、清洗器、熔断器这些模块，下个项目直接搬
3. **暴露隐性欠债**——哪些代码是"能跑但不理解"的，复盘时一测便知

## 二、复盘方法论（KPT + 4L 任选）

| 方法 | 结构 | 适合 |
|---|---|---|
| **KPT** | Keep（保持）/ Problem（问题）/ Try（尝试） | 迭代快的项目 |
| **4L** | Liked / Learned / Lacked / Longed for | 学习型复盘 |
| **STAR** | 情境-任务-行动-结果 | 汇报/面试 |

爬虫阶段建议 **4L**：学到的(Learned)直接对应知识清单，缺的(Lacked)变成下阶段补课列表。

## 五、收尾文档清单（Checklist）

一个项目"收尾"要交付什么：

- [ ] README（怎么跑、依赖、目录结构）
- [ ] 架构图（模块关系 + 数据流向）
- [ ] 配置样例（config.example，不含真实密钥）
- [ ] 已知问题与 TODO（诚实记录，别装完美）
- [ ] 数据/法律说明（抓了什么、依据什么授权）

> ⚠️ 避坑：**别把密钥写进收尾文档**。历史 commit 里的密钥即使删除也留在 git 历史里，等于永久泄露——需要 `git filter-repo` 才能真正清除。
