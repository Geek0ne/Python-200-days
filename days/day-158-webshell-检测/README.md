# Day 158 — WebShell 检测：离线审阅与证据关联

> Phase 10 — 网络安全开发。仅用于自己的离线文件副本和合成审计事件。
> 本课不生成或执行 WebShell，不发网络请求，不部署后门，不演示规避检测。

## 1. 学习目标与概念

WebShell 是通过 Web 服务访问的服务器端后门。它可滥用应用进程的权限，并不天然具有管理员权限，也不一定有图形界面。文件上传控制缺陷、应用漏洞或凭据泄露都可能导致后门落地，但仅凭文件名不能确认来源。

完成本课后，应能解释：静态规则为什么有误报、行为信号为什么需要关联，以及“没有发现”为什么不等于“确认安全”。

### 静态与行为的区别

- **静态审阅**：把文件当作数据读取，报告需复核的 API 名称与行号。不导入、不运行、不自动解码目标。
- **行为分析**：审阅已采集的文件事件、进程启动和访问日志。本课只处理合成事件，不采集真实机器的进程或连接。
- **证据关联**：同一主机、同一进程实例、合理时间窗口里的多个信号，比一个关键词更有参考价值。

`eval`、解码 API 和进程 API 在合法代码中也存在。正则命中无法证明外部输入到达危险调用；注释、教程和测试代码也可能命中。PHP 的字符串断言求值在 PHP 8 已移除，不能把旧版本行为当作新版本特征。

## 2. 开始练习（Python 3，Linux，无第三方依赖）

从仓库根目录执行：

```bash
python3 days/day-158-webshell-检测/code/01-static-scanner.py --self-test
python3 days/day-158-webshell-检测/code/02-behavior-hunter.py --self-test
python3 days/day-158-webshell-检测/code/03-webshell-scanner.py --self-test
```

三个命令都应输出 `SELF-TEST OK`。不加 `--self-test` 运行前两个例子，会显示临时文本扫描报告或合成事件分析报告。测试文件由 `TemporaryDirectory` 管理，结束即清理。

审阅自己的**稳定离线副本**时，显式指定路径：

```bash
python3 days/day-158-webshell-检测/code/03-webshell-scanner.py ./my-offline-copy
```

默认不扫描 `/var/www` 或整个系统。不使用多线程：教学实现优先保持顺序稳定、错误可追踪、资源开销可预测。

## 3. 代码导读

### `static_scan.py`：共享规则与文件读取

`inspect_text(text)` 返回规则名称及行号；`inspect_file(path)` 限制单文件读取到 1 MiB，跳过二进制、非 UTF-8、符号链接和特殊文件。`scan_tree(root)` 默认处理最多 1000 个文件条目，限制达到时标记 `truncated`。

Linux 的 `O_NOFOLLOW` 防止打开最终路径组件的符号链接；`O_NONBLOCK` 配合普通文件检查避免特殊文件阻塞。它们**不是完整沙箱**：并发替换父目录等恶意竞争不在本例保障范围。请只审阅已固定的离线副本，不以管理员身份扫描不可信的活动目录。

报告不会导出源码、命令参数或凭据。路径本身仍可能敏感，分享报告前也要脱敏。

### `01-static-scanner.py`：从误报开始理解规则

临时目录包含普通文档、API 名称索引、符号链接和二进制标记。名称索引会命中，但它只是不可执行文本。这个例子故意提醒：**规则命中是复核线索，不是恶意结论**。

### `02-behavior-hunter.py`：合成事件关联

输入是字典列表，每个事件带 `host`、`instance`、`role`、`kind`。同一 Web worker 实例同时出现上传区脚本写入和子进程启动，输出 `review_required`。进程实例标识必须包含启动身份，不能只用可复用的 PID。

本例假设输入已限定时间窗口；生产系统必须另外完成时间归一化、去重、采集完整性校验和主机身份核验。合法转换任务也可能启动子进程，仍需核对业务基线。

### `03-webshell-scanner.py`：CLI 与覆盖范围

支持本地目录、`--max-files` 和 `--self-test`，JSON 输出到标准输出。

| 字段 | 含义 |
|---|---|
| `files` | 每个文件的相对路径、状态、命中或跳过原因 |
| `truncated` | 是否因为文件数限制未完成遍历 |
| `walk_errors` | 目录访问错误类型；非空表示覆盖不全 |
| `findings` | 规则名称与行号，不含源代码 |

退出码 0：所有列出的文件成功扫描（即使命中规则）；退出码 2：参数错误、覆盖不完整或有跳过项。**0 不代表安全认证**。扫描器从不自动删除、隔离或上传文件。

## 4. 检测后的正确处理

1. 记录证据获取时间、来源、哈希以及业务基线，先保全原始文件和日志。
2. 人工检查命中位置是否位于注释、合法依赖或实际执行路径；不要运行可疑文件验证。
3. 将文件变化与同一时间窗的进程和访问事件关联，不单凭日志中的一个参数定植入时间。
4. 按组织事件响应流程限制受影响服务、轮换相关凭据，并排查最初的入口。
5. 修复后重新验证基线及日志覆盖。是否下线或删除应由负责人决定。

## 5. 自测覆盖与局限

覆盖：普通文本无命中、文档误报、多规则行号、二进制、非 UTF-8、超大文件、符号链接、文件数截断、缺失目录、只读哈希校验、跨主机和跨进程实例不误关联。

未覆盖：真实恶意样本检出率、各种语言语义分析、压缩包展开、生产流量、恶意并发目录替换。未扫描项必须保留在报告里，不得按“零告警”隐藏。
