# Day 099 — 性能对比分析

## 测试环境

- CPU: Intel/AMD x86_64
- Python: 3.12+
- Cython: 3.0+
- Pybind11: 2.12+
- 操作系统: Linux

## 基准测试结果

### 1. 斐波那契数列 (n=500,000)

```
纯 Python          ████████████████████████████  100%  ~2.2s
Cython (无类型)    ████████████████              55%   ~1.2s
Cython (全类型)    ██                            8%    ~0.18s
Pybind11 (C++)     █                             5%    ~0.11s
纯 C++             █                             4%    ~0.09s
```

### 2. 矩阵乘法 (100×100)

```

Cython             █                             5%    ~0.04s

```

### 3. 字符串处理 (100万次拼接)

```
纯 Python          ████████████████████████████  100%  ~1.5s
```

> 💡 字符串处理 Cython 优势明显，Pybind11 因为涉及类型转换反而较慢

### 4. 文件 I/O (读取 100MB 文件)

```

Cython             ████████████████████████████  95%   ~0.28s
Pybind11           ████████████████████████████  90%   ~0.27s
```

> 💡 I/O 密集型任务，C++ 加速效果有限（瓶颈在磁盘）

## 适用场景推荐

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| 数值计算循环 | Cython / Pybind11 | 消除 Python 解释器开销 |
| 调用已有 C++ 库 | Pybind11 | 最自然的绑定方式 |
| 加速现有 Python 代码 | Cython | 改动最小，渐进式优化 |
| 图像/信号处理 | Pybind11 | SIMD 优化空间大 |
| 机器学习推理 | Pybind11 | 模型核心用 C++ 实现 |
| 脚本/插件系统 | 嵌入 Python | C++ 主程序需要灵活扩展 |
| 快速原型 | Cython | 开发效率与性能的平衡 |
