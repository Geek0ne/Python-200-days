读法：等级取「能命中的最高级」，不是累加。 137 课停在 L2 意味着：代码写了，但没有一个断言能证明它今天还能跑。 这正是图 5 那个缺陷能存活 15 次提交的原因。

图 3：校准差要双向读

                 自评分
                   ^
              高   |   高估区              一致区
                   |   （补证据）          （别动）
                   |
        +----------+----------+----------+--------> 证据分
                   |          |          |
              低   |   一致区 |   低估区
                   |          |  （去外部验证：
                   |          |    面试 / 开源 / 读者）

  带宽 ±15 分（产品判断，不是统计结论）

  实测样例（self-rating.example.json，示例数据非真实自评）：
    语言与数据模型   证据 52.1  自评 85  → +32.9  高估
    安全与合规       证据 82.0  自评 55  → −27.0  低估
    表达与协作       证据 80.0  自评 40  → −40.0  低估

读法：两个方向的错，修法完全不同。 高估要回去补痕迹；低估要去找一个外部裁判——你缺的不是能力，是证据的见证人。

读法：虚线是盲区——git 里没有「我读了什么」，所以输入不能算 0，只能算「未测量」。 红框是实测瓶颈：反馈占 1.3%，低于 5% 阈值。 一个 94.3% 的提交都在「新增」的系统，本质上是单向管道，不是回路。

结论：指标不是被「造假」污染的，是被「粒度」污染的。
      一次改 199 课，不等于 199 课都被复盘过。

读法：这是本课最重要的一个原理。任何按「事件计数」的指标， 都要先问一句：一个事件能覆盖多少个对象？ 覆盖数一大，指标就失去分辨力。

图 8：放弃条件是一个状态机，不是一句丧气话

stateDiagram-v2 [*] --> 执行中 执行中 --> 已交付: 别人验收通过 执行中 --> 触发放弃条件: 到期仍未达标 触发放弃条件 --> 缩小范围: 砍到能交付的最小集 触发放弃条件 --> 换方向: 举证后重新立项 缩小范围 --> 执行中 换方向 --> [*] 已交付 --> [*] note right of 触发放弃条件 没有这条边，计划会永远停在「执行中」 三个月后既没交付也没复盘 end note
stateDiagram-v2
    [*] --> 执行中
    执行中 --> 已交付: 别人验收通过
    执行中 --> 触发放弃条件: 到期仍未达标
    触发放弃条件 --> 缩小范围: 砍到能交付的最小集
    触发放弃条件 --> 换方向: 举证后重新立项
    缩小范围 --> 执行中
    换方向 --> [*]
    已交付 --> [*]
    note right of 触发放弃条件
        没有这条边，计划会永远停在「执行中」
        三个月后既没交付也没复盘
    end note

读法：放弃条件的作用不是允许你认输，而是强制你在某个时刻重新举证。 它把「继续投入」从一个默认动作，变成一个需要理由的决策。
