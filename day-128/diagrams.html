Day 128 - Scrapy 框架 图解

1. Scrapy 架构总览（官方架构的精简版）

                        ┌──────────────┐
                        │   SPIDER     │  你写的解析逻辑
                        │ (parse 回调) │
                        └──────┬───────┘
                     Request ↑ │ ↓ yield Item
                        ┌──────┴───────┐        ┌─────────────┐
                        │    ENGINE    │───────►│  PIPELINE   │
                        │   (总调度)   │ Item   │ 清洗→去重→入库│
                        └──┬────────▲──┘        └─────────────┘
              Request      │        │  Response
                     ┌─────▼────────┴─────┐
                     │  DOWNLOADER        │
                     │  MIDDLEWARES       │  加 UA / 代理 / 重试
                     └─────┬────────▲─────┘
                     ┌─────▼────────┴─────┐
                     │  DOWNLOADER        │  异步并发下载
                     └─────┬────────▲─────┘
                           ▼        │
                     ┌──────────────┐
                     │  SCHEDULER   │  请求队列 + 去重过滤
                     └──────────────┘

2. 请求生命周期（时序）

sequenceDiagram participant S as Spider participant E as Engine participant Sc as Scheduler participant D as Downloader participant P as Pipeline S->>E: yield Request E->>Sc: 入队(去重) Sc-->>E: 取出队首请求 E->>D: 下载(经过 Downloader MW) D-->>E: Response E->>S: Response 回调 parse S->>P: yield Item S->>E: yield 新 Request(翻页) 
sequenceDiagram
    participant S as Spider
    participant E as Engine
    participant Sc as Scheduler
    participant D as Downloader
    participant P as Pipeline
    S->>E: yield Request
    E->>Sc: 入队(去重)
    Sc-->>E: 取出队首请求
    E->>D: 下载(经过 Downloader MW)
    D-->>E: Response
    E->>S: Response 回调 parse
    S->>P: yield Item
    S->>E: yield 新 Request(翻页)

3. 同步 vs 异步耗时对比

requests 串行（总耗时 = 各请求之和）:
  req1: [下载███][解析]
  req2:            [下载███][解析]
  req3:                     [下载███][解析]
  总计: ████████████████████████

Scrapy 异步（总耗时 ≈ 最慢请求）:
  req1: [下载███][解析]
  req2: [下载███][解析]
  req3: [下载███][解析]     ← 下载等待时间完全重叠
  总计: ███████
