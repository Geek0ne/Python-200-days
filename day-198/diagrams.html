1. fork 工作流

flowchart LR U[(upstream/main)] -->|Fork| F[(origin/main)] F -->|git switch -c| B[feature 分支] B -->|commit| C[gh-12345: fix typo] C -->|format-patch| P[0001-change.patch] P --> CI{CI + review} CI -->|request changes| B CI -->|approved| AM[maintainer: git am] AM --> U U -->|fetch + rebase| F 
flowchart LR
    U[(upstream/main)] -->|Fork| F[(origin/main)]
    F -->|git switch -c| B[feature 分支]
    B -->|commit| C[gh-12345: fix typo]
    C -->|format-patch| P[0001-change.patch]
    P --> CI{CI + review}
    CI -->|request changes| B
    CI -->|approved| AM[maintainer: git am]
    AM --> U
    U -->|fetch + rebase| F

读图要点：

  1. 你的分支永远在 fork 里，不直接写 upstream。
  2. 上游接受的是 patch（或等价的 PR 合并），不是你的分支引用。
  3. 同步方向只有一条：upstream → fork，且用 rebase 保持线性历史。

3. 三方合并

sequenceDiagram participant C as 贡献者 participant U as upstream participant R as reviewer U->>C: clone / fork C->>C: 基于 base 提交 patch U->>U: 修改同一区域（漂移） C->>R: 发送 patch R->>R: git am（严格上下文）→ 失败 R->>R: git am -3（base/ours/theirs） alt 改动不重叠 R->>U: 自动合并成功 else 同一行 R->>R: CONFLICT，手工解决 R->>U: git add + am --continue end 
sequenceDiagram
    participant C as 贡献者
    participant U as upstream
    participant R as reviewer
    U->>C: clone / fork
    C->>C: 基于 base 提交 patch
    U->>U: 修改同一区域（漂移）
    C->>R: 发送 patch
    R->>R: git am（严格上下文）→ 失败
    R->>R: git am -3（base/ours/theirs）
    alt 改动不重叠
        R->>U: 自动合并成功
    else 同一行
        R->>R: CONFLICT，手工解决
        R->>U: git add + am --continue
    end
